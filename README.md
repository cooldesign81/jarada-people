# 자라다 People — JP 통합 HR 시스템

Firebase(Authentication + Firestore + Storage) 위에서 동작하는 정적 웹앱입니다. 빌드 과정 없이 GitHub Pages로 배포됩니다.

- 앱 주소: https://cooldesign81.github.io/jarada-people/
- 초기 설정 페이지: https://cooldesign81.github.io/jarada-people/setup.html
- 휴대폰: 앱 주소를 열고 ‘홈 화면에 추가’(PWA)하면 앱처럼 쓸 수 있습니다.

| 주민번호 앞자리 채우기 | **관리 → 현황 점검 → 주민번호 앞자리 채우기**: 생년월일이 있는데 주민번호 앞자리가 비어 있는 직원(퇴직 포함)의 앞 6자리를 생년월일로 채웁니다(1990-05-21 → 900521). 이미 있는 앞자리와 뒷자리는 건드리지 않고, 작업은 감사로그에 남습니다 | 관리자 |
| 내 서류 | **내 정보 옆 ‘내 서류’ 메뉴**에서 본인의 공개·비공개 서류를 올립니다(내 정보 화면에는 서류가 없습니다). 최고관리자 등 권한자는 인사 평가 파일·기타도 여기서 다룹니다. 관리자가 다른 직원의 서류를 보고 올리는 곳은 그대로 직원 상세입니다 | 모두 |
| 내 명세서 | 직원이 **로그인하면 본인 급여 명세서·급여 세부내역서**를 보고 내려받음 (새 명세서 배지, 열람 시각 기록) | 모두 (본인 것만) |
| 조직 | 지점 관리, **조직도** | 모두 |
| 관리 | 내보내기·백업, 현황 점검(서류 미비·자격증 만료), 인건비(지점별), 감사 로그, 설정, 휴지통 | 최고관리자·본사 인사 (일부는 최고관리자 전용) |

달력 일정은 이 앱의 휴가 데이터와 직원 생년월일로 자동 그려집니다. 휴일은 2026·2027년 공휴일(대체공휴일 포함)이 내장돼 있고, 그 밖의 휴일·행사는 달력에서 직접 추가합니다. **내장 공휴일은 참고용입니다.** 임시공휴일 등은 직접 등록해 주세요.

### 회사 지정 휴가 (하계휴가 등): 전 직원 연차 차감
달력에서 일정을 등록할 때 종류를 **‘회사 지정 휴가 (전 직원 연차 차감)’**으로 고르면, 저장 직후 직원들의 연차에서 그 기간을 한꺼번에 차감할 수 있습니다. (일정만 등록해서는 연차가 줄지 않습니다. 달력의 일정과 직원의 연차는 별개이기 때문입니다.)
- 이미 ‘휴일’ 또는 ‘행사’로 등록해 둔 일정은 달력에서 눌러 **종류만 ‘회사 지정 휴가’로 바꾸고 저장**하면 됩니다. (‘휴일’ 종류는 휴가 일수에서 빠지는 날이라 연차가 차감되지 않습니다.)
- 미리보기 표에서 직원별 차감 일수, 현재 잔여, 차감 후 잔여를 보고 체크한 직원만 차감합니다. 주말·공휴일은 빼고 계산하며, **연차가 모자란 직원, 이미 겹치는 휴가가 있는 직원, 휴가 기간 중 입사했거나 입사일이 없는 직원은 기본으로 빠집니다**(부족한 직원은 직접 체크하면 포함). 휴직·퇴직 직원은 대상이 아닙니다.
- 차감은 직원마다 ‘승인된 연차’ 한 건으로 들어가 연차 잔여와 휴가 내역에 그대로 반영됩니다. 달력에는 직원별 칸 대신 일정 한 줄만 보입니다.
- 일정 수정창의 **‘차감 취소’**로 한꺼번에 되돌릴 수 있고(휴가는 취소 처리), 일정을 지울 때도 함께 되돌릴지 묻습니다. 지점을 고르면 그 지점 직원만 대상입니다.

### 생년월일 자동 채우기
주민등록번호를 등록·입력할 때 **생년월일이 비어 있으면 주민번호로 채웁니다** (직원 상세에서 주민번호 저장, 일괄 등록 모두). 뒷자리 첫 숫자로 세기를 알 수 있으면 정확하고, 앞자리만 있으면 나이(14~85세)로 추정하며 둘 다 안 맞으면 비워 둡니다. 이미 등록돼 있는 직원은 **관리 → 현황 점검 → 생년월일 채우기**에서 한꺼번에 계산해 미리 보고(추정은 표시) 선택한 직원에만 적용합니다. 주민번호 숫자는 화면에 보여 주지 않습니다.

### 휴가·연차 계산 방식

- 휴가 일수는 주말·휴일을 뺀 평일 수입니다. 반차는 0.5일.
- 연차: 입사 1년 미만은 개근한 달마다 1일(최대 11일), 1년 이상은 15일, 3년차부터 2년마다 1일 가산(최대 25일). 사용 기간은 입사 기념일부터 1년. **개근을 가정한 계산**이므로 실제와 다르면 ‘연차 조정’으로 맞추세요.
- 연차를 사용하는 휴가 종류는 연차·오전/오후 반차이고, 병가·경조·예비군·출산육아 등은 연차에서 빼지 않습니다.
- **예비군**(예전 ‘공가’): 신청창에서 종류를 예비군으로 고르면 **소집 통지서 · 훈련 참석 확인서**(PDF·이미지, 10MB 이하)를 첨부할 수 있습니다. 소집 통지서는 신청할 때, 훈련 참석 확인서는 훈련 뒤에 휴가 내역의 ‘서류’ 버튼으로 올려도 됩니다(승인 전후 모두). 내역·승인창에는 제출/미제출이 표시되고 ‘보기’로 열 수 있습니다. 올리기·교체·삭제는 본인과 최고관리자·대표이사·해당 지점 원장/부원장, 열람은 여기에 승인하는 실장·팀장까지입니다. 파일은 Storage `hr/{사번}/leave/`에 두고 열람·첨부·삭제는 감사로그에 남습니다. (이미 ‘공가’로 저장된 기록은 같은 종류라 ‘예비군’으로 표시됩니다.)

## 처음 설정하는 순서

1. **Firestore 규칙 게시** — Firebase 콘솔 → Firestore Database → *규칙* 탭에 `firestore.rules` 내용을 붙여넣고 **게시**.
2. **Storage 켜기 + 규칙 게시** — Storage → 시작하기 → *규칙* 탭에 `storage.rules` 붙여넣고 **게시**. 이 규칙은 Firestore 의 권한 문서를 참조하므로, 게시할 때 콘솔이 권한 부여를 물으면 허용합니다.
3. **로그인 방법** — Authentication → Sign-in method: `Google` 사용, 등록 링크용으로 `익명(Anonymous)` 도 사용 설정. 설정 → 승인된 도메인에 `cooldesign81.github.io` 추가.
4. **최초 관리자 등록** — `setup.html`에서 구글 로그인 → UID 복사 → Firestore `roles` 컬렉션에 문서 ID = UID 로 생성:
   - `level` = `super`
   - `orgId` = `hq`
   - `employeeId` = `emp_0001`
5. **앱 진입** — `index.html` 로 이동하면 본사(`orgs/hq`)가 자동 생성됩니다. *내 정보* 탭에서 본인 직원 정보를 등록합니다.
6. **조직(지점) 등록** — *조직* 탭에서 평촌원·반포원·대치원 등을 추가합니다.
7. **직원 등록** — *직원* 탭에서 한 명씩 등록하거나 **일괄 등록**을 씁니다.
8. **직원 본인 입력** — 직원 상세의 **등록 링크 복사**로 링크를 보내면, 직원이 로그인 없이 자기 개인정보·주민번호·서류를 직접 올립니다. 링크는 기본 14일 뒤 만료되며(관리 → 설정에서 변경), 직원 상세에서 재발급·폐기할 수 있습니다. 구글 계정 이메일로 등록된 직원은 그 계정으로 로그인해도 같은 화면을 씁니다.

> 규칙은 **코드를 올릴 때마다 콘솔에 다시 게시**해야 반영됩니다. 이번 업데이트(휴가·공지·인사 기록 등)는 `firestore.rules` 와 `storage.rules` 둘 다 바뀌었습니다.

## 권한(`level`)

| 등급 | 범위 |
|---|---|
| 최고관리자 (`super`) | 전체. 급여·주민번호 뒷자리·비공개서류·감사 로그·설정·인건비 |
| 대표이사 (`hr`) | 모든 지점의 직원·휴가·공지·인사 기록. 급여·주민번호 뒷자리·비공개서류는 볼 수 없음 |
| 원장 (`principal`) / 부원장 (`admin`) | 소속 지점 직원 관리, 휴가 승인, 지점 공지 |
| 실장 (`manager`) / 팀장 (`lead`) | 소속 지점 직원 조회, 휴가 승인, 면담 기록 (수정·등록 권한은 없음) |
| 사원 (`staff`) | 본인 정보, 휴가 신청, 공지 읽기, 달력(본인 생일·휴가 + 공통 휴일·행사) |
| 교육팀 (`edu`) | 예전 등급. 이미 부여된 사람만 유지되고 새로 부여할 수는 없음 (자격증·교육 이수 관리) |

### 권한 설정 (관리 → 권한 설정, 최고관리자 전용)

위 표는 **기본값**입니다. 최고관리자는 *관리 → 권한 설정*에서 아래 기능을 등급별로 켜고 끌 수 있고, 저장하면 보안 규칙에도 바로 적용됩니다(`settings/permissions`). 설정이 없으면 기본값을 씁니다. 최고관리자의 권한은 바꿀 수 없습니다.

- 완전 삭제, 권한 문서(roles) 관리, 설정·전체 백업은 최고관리자 고정입니다. 사원에게는 관리 권한을 줄 수 없습니다.
- 급여·주민번호 뒷자리·비공개서류를 열어 주면 해당 등급이 개인정보를 볼 수 있게 되므로 신중히 켜세요. 변경은 감사 로그에 남습니다.

예전 이름과의 대응: 본사 인사 → 대표이사, 관리자 → 부원장, 직원 → 사원. 저장된 값(`hr`, `admin`, `staff`)은 그대로이고 화면 이름만 바뀌었습니다. 팀장은 새 등급이며, 팀 단위 구분이 없어 현재는 실장과 같은 권한입니다.

직원의 상태를 **퇴직**으로 바꾸면 연결된 `roles` 문서가 삭제되어 로그인 권한이 사라집니다. 직원 삭제는 먼저 **휴지통**으로 가고, 관리 → 휴지통에서 복원하거나 완전히 삭제합니다.

**소속 법인**은 지점과 별개로 직원마다 하나를 고릅니다(기본 정보 수정, 일괄 등록의 ‘소속 법인’ 열). 재직·경력증명서는 직원의 소속 법인으로 발급되며(법인명·대표자·주소·직인), 법인이 지정돼 있으면 증명서 창에서 고정됩니다. 급여 명세서·근로계약서도 이 법인이 기본으로 선택됩니다. 법인이 바뀌면 발령·변경 이력에 기록됩니다.

**급여 명세서 · 근로계약서 초안 · 퇴직금 예상**은 급여 정보 구역에서 최고관리자만 만듭니다.

- 급여 명세서: 지급 내역은 급여 정보에서 가져오고, 공제(4대보험·세금)는 **직접 입력**합니다. 요율이 해마다 바뀌어 자동 계산하지 않습니다.
- 근로계약서: 입력한 정보로 만든 **초안**입니다. 사용 전에 노무사·변호사의 검토를 받으세요.
- 퇴직금 예상: 월 고정급(기본급+식대+추가급여)만으로 1일 평균임금을 어림잡은 값입니다. 상여금·연차수당·인센티브는 빠져 있어 실제와 다를 수 있습니다.
- 지점별 인건비(관리 → 인건비)도 월 고정급만 합산하며 4대보험 사업주 부담분은 포함하지 않습니다.

## 급여 명세서·급여 세부내역서 배포

최고관리자(또는 권한 설정에서 ‘급여 정보’를 열어 준 대표이사)가 **관리 → 급여 배포**에서 올립니다. 문서는 두 종류입니다: **급여 명세서**, **급여 세부내역서**(인센티브 내역).

1. **종류**와 **귀속 월**을 고릅니다.
2. PDF 또는 이미지 파일(한 파일 10MB 이하)을 여러 개 한꺼번에 끌어다 놓습니다. **파일 이름에는 직원 이름만** 있으면 됩니다 (예: `김교사.pdf`). 이름으로 직원을 자동으로 맞추고(사번·이메일도 인식), 못 찾았거나 동명이인인 파일은 표에서 직접 고릅니다. 한 직원의 파일이 두 개 들어오면 두 번째는 막힙니다.
3. “N건 올리기”를 누르면 올라가고, 같은 직원·종류·월에 다시 올리면 새 파일로 **교체**됩니다. 종류·월이 다르면 따로 올립니다.
4. 직원은 **본인 구글 계정으로 로그인**해 ‘내 급여’ 탭에서 봅니다. 안 읽은 문서는 탭에 배지가 뜨고, 처음 열면 열람 시각이 남습니다.
5. *월별 배포 현황*에서 누가 받았고 열어 봤는지 확인합니다. **배포한 뒤에도 고칠 수 있습니다**: 각 칸의 **보기 / 종류·월 수정**(잘못 고른 월·종류 바로잡기) **/ 파일 교체 / 삭제**, 그리고 **‘이 달 ○○ 전체 삭제’**(잘못 올린 묶음을 통째로 취소)가 있습니다. 직원 상세의 ‘급여 명세서·세부내역서’에서도 개별 삭제할 수 있습니다. 종류·월을 고쳐도 직원 화면에는 바로 반영되고, 같은 종류·월에 이미 문서가 있으면 막습니다.

### 급여 열람 비밀번호 (열 때마다 한 번 더)
- 직원은 처음 열 때 **급여 열람 비밀번호**를 직접 정합니다(8자 이상, 숫자만·같은 글자 반복 불가). 이 비밀번호는 구글 로그인 비밀번호와 별개입니다.
- 그다음부터는 명세서를 **보기·다운로드할 때마다** 비밀번호를 다시 입력해야 합니다. 로그아웃하지 않은 자리에서 다른 사람이 급여를 보는 것을 막기 위한 장치입니다. 5번 틀리면 1분간 막히고, 이 사실이 감사 로그에 남습니다. ‘내 급여’ 화면에서 비밀번호를 바꿀 수 있습니다(현재 비밀번호 필요).
- 비밀번호를 잊으면 **급여 권한자가 직원 상세 → ‘초기화’**를 눌러 지워 줍니다. 직원은 다음에 열 때 새로 정합니다. (직원 스스로 초기화할 수는 없습니다 — 자리를 비운 사이 다른 사람이 바꾸지 못하게)
- 비밀번호는 저장하지 않고, 소금을 섞어 여러 번 해시한 값만 보관합니다 (`private/payLock`).
- **한계:** 이 확인은 브라우저 화면에서 이루어지고 서버가 강제하지는 않습니다. 그래서 *지나가던 사람이 열려 있는 화면에서 보는 것*은 막지만, 개발자 도구를 다룰 줄 아는 사람이 로그인된 브라우저를 오래 쓸 수 있다면 우회할 수 있습니다. 자리를 비울 때 로그아웃하거나 화면을 잠그는 습관과 함께 쓰세요.

- 직원 본인과 급여 권한자만 열 수 있습니다. **등록 링크로 들어온 사람은 볼 수 없습니다.** 원장·부원장·실장도 볼 수 없습니다.
- 직원이 구글 계정으로 한 번이라도 로그인해 권한이 연결돼 있어야 합니다 (직원 이메일 = 구글 계정 이메일).
- 열람·다운로드·업로드·삭제·비밀번호 설정·초기화는 감사 로그에 남습니다. 직원 완전 삭제 시 명세서 파일도 함께 지워집니다.

## 일괄 등록

*직원 → 일괄 등록*에서 엑셀·구글시트의 표를 복사해 붙여넣거나 **CSV / 엑셀(.xlsx) 파일**을 올립니다. `양식 내려받기`의 제목 줄을 쓰면 열 순서가 달라도 자동으로 맞춥니다. (엑셀 파일을 읽을 때 SheetJS 를 인터넷에서 불러옵니다.)

열: 이름, 이메일, 소속 지점, 직책, 전번, 입사일, 권한, 상태, 생년월일, 수습 종료일, 계약 만료일, 주소, 계좌번호, 보호자 성명·관계·연락처, 교육시작일, 근로시작일, 4대보험 등록일, 퇴사일, 그리고 최고관리자 전용 급여 열. 금액은 `1,000,000`·`100원`처럼 쉼표나 ‘원’이 있어도 읽습니다.

- 소속 지점은 이름 또는 ID 로 적고 여러 곳이면 `평촌원/반포원` 처럼 `/` 로 구분합니다.
- **‘기존 직원 수정’**을 켜면(본사 인사 이상) 이미 등록된 이메일은 새로 만들지 않고 **채워진 칸만** 덮어씁니다. 비워 둔 칸은 그대로입니다.
- - **주민등록번호**도 넣을 수 있습니다. ‘주민등록번호’ 열에 `900101-1234567`(또는 앞·뒤 열을 따로) 적으면 됩니다. 엑셀이 앞의 0을 지운 값(`10101`)도 읽어 채우고, 미리보기에는 숫자를 보여 주지 않습니다. **뒷자리는 저장 권한(권한 설정의 ‘주민번호 뒷자리’, 기본은 최고관리자)이 있고 설정에서 수집을 끄지 않았을 때만** 들어가며, 아니면 그 줄은 오류가 됩니다 (앞자리만 넣으면 됩니다).
- 오류가 있는 줄은 건너뛰고 정상인 줄만 처리합니다. 서류·퇴직금 중간정산은 일괄 등록하지 않습니다.

## 보안 참고 (꼭 읽어 주세요)

- **주민등록번호와 급여는 Firestore 에 암호화 없이 저장됩니다.** 접근은 보안 규칙으로만 제한되므로 규칙 게시와 최고관리자 계정 보호가 중요합니다. 암호화 저장은 Cloud Functions(서버 코드)가 필요해 이 정적 앱만으로는 할 수 없습니다. 뒷자리를 더 이상 받지 않으려면 관리 → 설정에서 수집을 끄세요.
- 이 앱이 하지 못하는 보안 항목: 구글 계정 2단계 인증 강제, Firebase App Check, 이상 접근 이메일 알림, 서버 쪽 자동 백업. 2단계 인증은 구글 계정 설정에서, 자동 백업은 Firebase 콘솔 → Firestore → 재해 복구에서 켭니다.
- **감사 로그**에 민감정보 열람·수정, 파일 업로드·다운로드·삭제, 급여 변경, 증명서 발급, 일괄 작업이 남습니다. (앱을 거치지 않고 콘솔에서 직접 바꾼 것은 기록되지 않습니다.)
- 등록 링크를 아는 사람은 해당 직원의 입력 페이지에 접근할 수 있습니다. 링크는 직원 본인에게만 전달하고, 유출이 의심되면 상세 화면에서 **폐기**하세요(만료일이 지나도 막힙니다).
- 직원은 본인 직원 문서를 규칙상 읽을 수 있어 `memo`(관리자 메모)도 읽힙니다. 화면에는 표시하지 않지만 민감한 내용은 메모에 적지 마세요.
- 공지는 직원의 **대표 지점** 기준으로 지점 공지가 보입니다. 두 지점 이상 겸직하는 직원은 대표 지점이 아닌 쪽의 지점 공지가 보이지 않을 수 있습니다(전체 공지는 모두 보임).
- 달력에는 권한 범위 안의 생일·휴가만 나옵니다. 본사 인사 이상은 전체, 원장·관리자·실장은 소속 지점 직원, 일반 직원은 본인 것만 보입니다. 직원끼리 서로의 생일·휴가를 보게 하려면 보안 규칙(`employees` 읽기, `leaveRequests` 읽기)을 넓혀야 하는데, 그러면 직원이 동료의 연락처·메모까지 읽을 수 있게 되므로 기본값은 막아 두었습니다.

## 테스트

`tests/` 에 자동 테스트가 있습니다 (배포에는 쓰이지 않음). Node 22 와 Java 21(에뮬레이터용)이 필요합니다.

```bash
cd tests
npm install
npx playwright install chromium
npm run test:unit    # 연차·휴가 일수·공휴일·급여 계산
npm run test:rules   # Firestore·Storage 보안 규칙 (Firebase 에뮬레이터)
npm run test:e2e     # 화면 동작 (가짜 Firebase 로 브라우저 자동 조작)
```

- 보안 규칙 테스트는 역할별(대표·본사 인사·교육팀·원장·실장·직원·로그인 안 함)로 “되어야 하는 것”과 “막혀야 하는 것”을 모두 검사합니다. Storage 규칙은 에뮬레이터가 다른 서비스(Firestore) 조회를 지원하지 않아, 조회 부분만 토큰으로 바꾼 사본(`tests/rules/make-shim.cjs`)으로 검사합니다.
- 화면 테스트는 실제 Firebase 에 접속하지 않고 `tests/e2e/mocks/` 의 가짜 모듈을 씁니다. 그래서 규칙이 실제로 허용하는지는 검증하지 못합니다 (그건 규칙 테스트의 몫).
- GitHub Actions(`.github/workflows/test.yml`)가 풀 리퀘스트마다 위 테스트를 돌립니다.

